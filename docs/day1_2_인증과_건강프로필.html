03회원가입 POST /users

컬럼누가 채우나요청으로 받나
idDB 자동 증가받지 않음
email사용자 (EmailStr로 형식 검사)받음
password_hash서버가 password를 해싱password로 받음
created_atDB (server_default=func.now(), UTC)받지 않음
@router.post("/users", summary="회원가입 API", status_code=201,
             response_model=SignUpResponse)       # 응답에서 password_hash를 걸러냄
async def sign_up_handler(body: SignUpRequest, session = Depends(get_session)):
    # [1] 이메일 중복 검사 → 있으면 409 Conflict
    stmt = select(User).where(User.email == body.email)
    result = await session.execute(stmt)
    if result.scalar():
        raise HTTPException(status_code=409, detail="이미 가입된 이메일입니다.")

    # [2] 비밀번호 해싱 → [3] 저장
    new_user = User(email=body.email, password_hash=hash_password(body.password))
    session.add(new_user)
    await session.commit()
    await session.refresh(new_user)              # DB가 채운 id·created_at 다시 읽기
    return new_user

처음 코드에서 빠져 있던 3가지

파일증상고친 것
router.pyresponse_model=... 자리만 있음 → 응답 필터링이 안 됨response_model=SignUpResponse
router.pycommit 뒤 created_at을 읽다가 MissingGreenletawait session.refresh(new_user)
response.pyORM 객체(User)를 응답 모델로 못 바꿈model_config = ConfigDict(from_attributes=True)

created_at은 파이썬이 아니라 DB가 저장 순간에 채우는 값이라, commit 직후 객체에는 아직 없다. 비동기 세션에서는 나중에 몰래 읽어 오는(lazy load) 게 막혀 있어서 에러가 난다. refresh로 미리 읽어 오면 해결된다.

04비밀번호 해싱 (bcrypt)

  • 단방향: 해시에서 원래 비밀번호로 되돌릴 수 없다. DB가 털려도, 내부 직원이 봐도 원문을 모른다
  • 솔트: 비밀번호에 랜덤 값을 섞어서 같은 비밀번호도 매번 다른 해시가 나온다 → 자주 쓰는 비밀번호를 미리 해시해 둔 표(레인보우 테이블)가 쓸모없어진다
  • 검증: 같은 입력 + 같은 솔트면 같은 해시가 나온다. 솔트는 해시 문자열 안에 들어 있어서, checkpw가 그걸 꺼내 다시 해싱한 뒤 비교한다

버전·비용 └──── 솔트 22자 ────┘ └──────── 해시값 31자 ────────┘
12 = 2^12번 반복 → 일부러 느리게 해서 무차별 대입을 어렵게
# user/auth.py — bcrypt는 bytes만 받는다
def hash_password(plain_password: str) -> str:
    hashed = bcrypt.hashpw(plain_password.encode(), bcrypt.gensalt())   # str → bytes
    return hashed.decode()                                              # bytes → str (DB 저장용)

def verify_password(plain_password: str, password_hash: str) -> bool:
    return bcrypt.checkpw(plain_password.encode(), password_hash.encode())

05로그인 POST /users/login

  1. email로 사용자 조회 → 없으면 401 (회원가입과 반대로 "없으면" 문제)
  2. verify_password로 확인 → 틀리면 401
  3. create_access_token(user.id) → {"access_token": "eyJ..."}
실패 메시지를 하나로 통일한 이유

"없는 이메일"과 "틀린 비밀번호"를 따로 알려 주면, 공격자가 가입된 이메일만 골라낼 수 있다(계정 열거). 그래서 둘 다 같은 401과 같은 문구로 응답한다. 다만 이메일이 있을 때만 bcrypt가 돌아서 응답이 느려지니, 시간 차로 구분하는 공격(타이밍 공격)도 있다는 것까지 알아 두자.

06JWT: 하루짜리 출입증

HTTP는 이전 요청을 기억하지 않는다. 매 요청마다 이메일과 비밀번호를 보내면 그때마다 DB를 조회하고 bcrypt를 돌려야 한다. 그래서 로그인 때 한 번만 확인하고, 이후엔 서버가 서명한 토큰만 보여 주게 한다.

  • sub는 토큰의 주인(user id). JWT 표준이라 문자열로 넣는다 → str(user_id)
  • exp는 만료 시각(유닉스 초). 이 프로젝트는 24시간. 없으면 영원히 쓸 수 있는 토큰이 된다
  • 헤더·페이로드는 Base64 인코딩일 뿐이라 누구나 풀어 볼 수 있다. 비밀번호나 개인정보는 넣지 않는다
  • 대신 서명은 비밀 키 없이는 만들 수 없다. sub만 바꿔 위조해도 서명이 맞지 않아 거절된다

비밀 키 관리가 전부다

서명 키를 아는 사람은 아무 user id로나 토큰을 찍어 낼 수 있다. 키는 .env의 JWT_SECRET_KEY에만 두고(openssl rand -base64 32로 생성), 깃·노션·jwt.io 같은 외부 사이트에 붙여 넣지 않는다. 퇴사자가 있거나 유출이 의심되면 바로 바꾼다.

def create_access_token(user_id: int) -> str:
    payload = {
        "sub": str(user_id),
        "exp": datetime.now(timezone.utc) + timedelta(hours=24),
    }
    return jwt.encode(payload=payload, key=settings.jwt_secret_key, algorithm="HS256")

07토큰 검증: 놓쳤던 return

건강 프로필 API는 user_id = Depends(verify_user) 한 줄로 "로그인한 사람만" 쓸 수 있게 했다. user id를 본문으로 받지 않는 이유는, 그러면 남의 id를 적어서 남의 프로필을 만들 수 있기 때문이다. 본문에는 건강 데이터만, 누구인지는 토큰의 sub로.

토큰을 넣었는데 500 에러

jwt.decode()가 푼 결과를 변수에 받지 않고 버려서, 함수가 None을 돌려줬다. 그다음 줄 payload.get("sub")에서 None에는 .get이 없으니 AttributeError가 났다.

def verify_access_token(access_token: str):
    try:
        jwt.decode(
        payload = jwt.decode(
            jwt=access_token,
            key=settings.jwt_secret_key,   # 서명 확인
            algorithms=["HS256"],          # 허용 목록 (encode는 algorithm 하나)
        )
    except jwt.DecodeError:
        raise HTTPException(status_code=401, detail="잘못된 토큰 형식입니다.")
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="만료된 토큰입니다.")
    return
    return payload

def verify_user(auth_header = Depends(HTTPBearer())):   # "Bearer xxx"에서 토큰만 꺼냄
    payload = verify_access_token(auth_header.credentials)
    user_id = payload.get("sub")
    if not user_id:
        raise HTTPException(status_code=401, detail="sub 값이 없습니다.")
    return int(user_id)

고친 뒤 직접 확인: create_access_token(7)로 만든 토큰을 검증하면 sub: 7이 나오고, 아무 문자열("abc")을 넣으면 401 잘못된 토큰 형식입니다.가 나온다.

08건강 프로필 테이블

class UserHealthProfile(Base):
    __tablename__ = "user_health_profile"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    user_id: Mapped[int] = mapped_column(ForeignKey("user.id"), unique=True)   # 회원당 1개

    age: Mapped[int] = mapped_column(Integer)
    height_cm: Mapped[float] = mapped_column(Float)          # 단위를 이름에 → 착오 방지
    weight_kg: Mapped[float] = mapped_column(Float)
    smoking: Mapped[bool] = mapped_column(Boolean)
    exercise_per_week: Mapped[int] = mapped_column(Integer)
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
  • ForeignKey("user.id")에는 클래스 이름이 아니라 __tablename__을 쓴다. 이 프로젝트의 테이블 이름은 user
  • unique=True로 1:1 관계(마지막 상태만 유지). 측정 기록을 쌓아 그래프를 그리려면 unique를 빼고 1:N으로 간다
  • 요청 양식 CreateHealthProfileRequest에는 user_id가 없다. 토큰에서 꺼내니까

★오늘의 핵심 5줄

  1. 비밀번호는 솔트를 섞은 bcrypt 해시로 저장하고, 검증은 checkpw가 해시 속 솔트로 다시 해싱해 비교한다
  2. 응답은 response_model로 걸러야 password_hash가 새지 않고, DB가 채우는 값은 refresh로 다시 읽는다
  3. 로그인 실패는 이메일·비밀번호 구분 없이 같은 401 + 같은 메시지
  4. JWT 페이로드는 누구나 읽지만 서명은 비밀 키 없이는 못 만든다. 키 관리가 전부다
  5. 함수가 값을 계산만 하고 return하지 않으면 None이다. user id는 본문이 아니라 토큰의 sub에서
