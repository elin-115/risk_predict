# 건강 예측 프로젝트 진행상황

## 프로젝트 개요
- 입력: 나이, 키, 몸무게, 흡연 여부, 주당 운동 횟수 (건강 프로필)
- 출력: 당뇨, 고혈압 위험도 (0~1 확률, OpenAI LLM이 계산)
- 기능: 회원가입, 로그인(JWT), 건강 프로필 등록, 위험도 예측


## 3. 테이블 생성
`python -m asyncio`로 비동기 REPL을 열어 `init_db()`를 실행했다.
```python
>>> from database.orm import init_db
>>> from user.model import User, UserHealthProfile   # 모델을 import 해야 테이블이 만들어진다
>>> from prediction.model import HealthRiskPrediction
>>> await init_db()
```
- 실행하면 `project.db` 파일이 생긴다. DBeaver에서 테이블을 확인했다.
- 처음에 `await init_db`로 괄호를 빠뜨려서 `TypeError: object function can't be used in 'await' expression` 에러가 났다. 함수는 호출해야 코루틴이 나오고, 그 코루틴을 await 해야 한다.
- `create_all`은 이미 있는 테이블은 건너뛴다. 컬럼을 고쳐도 기존 테이블에는 반영되지 않으므로 테이블을 지우고 다시 만들어야 한다.

## 4. 회원가입 — `POST /users`
사용자 정보를 DB에 저장하는 기능이다.

### 1단계: 요청·응답 형태 정하기
- `user/request.py` → `SignUpRequest(email, password)`
- `user/response.py` → `SignUpResponse(id, email, created_at)`
- 응답에 `password_hash`가 나가지 않도록 `response_model`로 필드를 제한했다.

### 2단계: 비밀번호 해싱
비밀번호를 알아볼 수 없게 저장하되, 로그인할 때 다시 확인할 수 있어야 한다.
1. 해시는 되돌릴 수 없어야 한다 (복호화 불가).
2. bcrypt는 salt(랜덤 값)를 섞기 때문에 같은 비밀번호도 매번 다른 해시가 나온다. 확인할 때는 해시 안에 저장된 salt로 다시 해싱해서 비교한다 (`bcrypt.checkpw`).
3. bcrypt는 문자열이 아니라 bytes를 받으므로 `.encode()`로 바꿔서 넣는다.

```python
>>> import bcrypt
>>> plain_password = "mypassword"
>>> plain_password.encode()
b'mypassword'
>>> bcrypt.hashpw(plain_password.encode(), bcrypt.gensalt())
b'$2b$12$NwI2Bvf6ZVk9YoqXpuwHJ.8WxIYS/kHGH49KFteIyrTxa.9t7KP7a'
```

### 3단계: 라우터 핸들러
1. 이메일 중복 검사 → 있으면 `409 Conflict`
2. 비밀번호 해싱
3. DB 저장 → `commit` → `refresh` → `201 Created`로 응답

### 놓쳤다가 고친 부분
| 위치 | 문제 | 해결 |
|---|---|---|
| `router.py` | `response_model=...` 자리만 잡혀 있었음 | `response_model=SignUpResponse` |
| `router.py` | commit 뒤 `created_at`을 못 읽어 `MissingGreenlet` 에러 | `await session.refresh(new_user)` 추가 |
| `response.py` | ORM 객체를 응답으로 못 바꿈 | `ConfigDict(from_attributes=True)` 추가 |
| `config.py` | `open_api_key`가 `.env`의 `OPENAI_API_KEY`와 안 맞음 | `openai_api_key`로 수정 |

## 5. 로그인 — `POST /users/login`
시스템/서비스에 사용 인증을 받는 기능이다.

1. 이메일로 사용자 조회 → 없으면 `401`
2. `verify_password`로 비밀번호 확인 → 틀리면 `401`
   - 이메일이 틀렸는지 비밀번호가 틀렸는지는 구분해서 알려주지 않는다 (보안).
3. `create_access_token`으로 JWT 발급 → `{"access_token": "..."}` 응답

### JWT (JSON Web Token)
- 로그인에 성공하면 발급하는 출입증이다. 이후 요청 헤더에 `Authorization: Bearer <토큰>`으로 넣는다.
- payload에 `sub`(사용자 id)와 `exp`(만료 시간, 24시간)를 넣고 `JWT_SECRET_KEY`로 서명한다.
- `http://127.0.0.1:8000/docs`에서 회원가입 → 로그인으로 토큰을 받은 뒤 https://www.jwt.io/ 에 넣어 구조(header / payload / signature)를 확인했다.

## 6. 건강 프로필 — `POST /health-profiles` (3일차 완료)
토큰의 사용자 id와 본문의 건강 데이터를 합쳐서 저장한다.

1. `verify_user`를 `Depends`로 걸어서 토큰이 있어야만 호출된다. user_id는 본문이 아니라 토큰의 `sub`에서 꺼낸다.
2. 같은 user_id의 프로필이 이미 있으면 `409 Conflict`
3. `body.model_dump()`로 요청 본문을 딕셔너리로 바꾸고 `UserHealthProfile(user_id=user_id, **profile_data)`로 객체를 만든다.
4. `commit` → `refresh` → `UserHealthProfileResponse`로 응답 (`201`)

```python
profile_data = body.model_dump()    # {"age": 30, "height_cm": 170.0, ...}
new_profile = UserHealthProfile(user_id=user_id, **profile_data)
session.add(new_profile)
await session.commit()
await session.refresh(new_profile)
return new_profile
```

- 응답 양식 `UserHealthProfileResponse`에도 `ConfigDict(from_attributes=True)`를 넣어야 ORM 객체를 응답으로 바꿀 수 있다.
- Swagger에서 기능별로 묶이도록 라우터에 `APIRouter(tags=["User"])`를 붙였다.

## 7. 위험도 예측 — `POST /predictions` (3일차)
로그인한 사용자의 건강 프로필을 OpenAI에 보내 당뇨·고혈압 위험도를 받고, 결과를 DB에 저장한다.

### 처리 순서
1. 토큰의 user_id로 건강 프로필 조회 → 없으면 `404`
2. 지난 24시간 안에 예측한 기록이 있으면 `409` (같은 데이터로 API 요금이 반복해서 나가지 않게)
3. `predict_health_risk()`로 OpenAI 호출
4. `HealthRiskPrediction`으로 저장 → `commit` → `refresh` → `201`

### 모델 선택 (요청 본문)
```python
model_version: Literal["gpt-5-mini", "gpt-6-luna"] = Body("gpt-5-mini", embed=True)
```
- `Literal`: 정해진 값만 받는다. Swagger에 드롭다운으로 보이고, 다른 값이 오면 `422`
- `Body(..., embed=True)`: 본문 값이 하나뿐일 때 `{"model_version": "gpt-5-mini"}`처럼 키로 감싸서 받는다. 없으면 `"gpt-5-mini"` 문자열 하나만 보내야 한다.

### OpenAI 호출 (`prediction/llm.py`)
```python
class RiskPredictionResult(BaseModel):
    diabetes_probability: float
    hypertension_probability: float

response = await client.responses.parse(
    model=model_version,
    input=prompt,
    text_format=RiskPredictionResult,   # 이 양식대로만 답하게 강제 (구조화된 출력)
)
return response.output_parsed           # 이미 RiskPredictionResult 객체
```
- 답을 자유 문장이 아니라 정해진 필드로 받으니까 문자열을 파싱할 필요가 없다.
- API 키는 `config.py`가 `.env`에서 읽은 `settings.openai_api_key`를 쓴다.

### 동기 vs 비동기
- `predict_health_risk`는 OpenAI 응답을 `await`로 기다리므로 `async def`로 만들었다. 기다리는 동안 서버가 다른 요청을 처리할 수 있다.
- `await` 할 일이 없는 순수 계산 함수(BMI 계산 등)는 그냥 `def`로 둔다.
- 객체 생성 `HealthRiskPrediction(...)`은 DB를 건드리지 않으므로 `await`를 붙이지 않는다. `await`는 `commit`, `refresh`, `execute`처럼 DB와 통신하는 곳에만 붙인다.

### 테스트 순서 (Swagger)
1. `POST /users/login` → `access_token` 복사
2. 오른쪽 위 **Authorize**에 토큰 붙여 넣기
3. (프로필이 없다면) `POST /health-profiles`로 프로필 생성
4. `POST /predictions`에 `{"model_version": "gpt-5-mini"}` → `201`
5. 같은 요청을 한 번 더 → `409 24시간 내에 예측한 결과가 존재합니다.`

### 3일차 에러 기록
| 증상 | 원인 | 해결 |
|---|---|---|
| 서버 reload 실패, 8000 포트가 꺼짐 | `responses_model` 오타 | `response_model` |
| `no such column: user_health_profile.model_version` | `model_version`을 프로필 모델에 잘못 넣음 | `HealthRiskPrediction`으로 옮기고 테이블 DROP 후 `init_db()` |
| `SyntaxError` | `Body(...)` 파라미터 뒤 쉼표 누락 | 쉼표 추가 |
| `TypeError ... unexpected keyword argument 'imput'` | `responses.parse`의 인자 오타 | `input` |
| `TypeError` (await 객체) | `await HealthRiskPrediction(...)` | 객체 생성에는 await를 빼기 |
| `404 건강 프로필이 존재하지 않습니다.` | DB를 비운 뒤에도 옛날 계정의 토큰을 Authorize에 계속 사용 | 다시 로그인해서 새 토큰으로 Authorize |

- JWT는 서명과 만료만 검사하기 때문에, DB에서 지워진 계정의 토큰도 24시간 동안은 통과한다.
