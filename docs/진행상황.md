## 1. 개발 환경 세팅

### 가상환경
conda 환경을 끄고 프로젝트 전용 venv를 만들었다.
```bash
conda deactivate
python3 -m venv .venv
source .venv/bin/activate
```

### 라이브러리 설치
```bash
pip install "fastapi[standard]" "sqlalchemy[asyncio]" aiosqlite   # 서버, ORM, 비동기 SQLite 드라이버
pip install bcrypt pyjwt                                          # 비밀번호 해싱, JWT 토큰
pip install pydantic-settings                                     # .env 읽기
pip freeze > requirements.txt                                     # 설치 목록 저장
```

### 추가 파일
| 파일 | 역할 |
|---|---|
| `config.py` | `.env`의 비밀 값을 읽어오는 설정 |
| `.env` | API 키, JWT 비밀키 (깃에 올리지 않음) |
| `.env.example` | `.env`에 어떤 키가 필요한지 보여주는 빈 양식 |
| `.gitignore` | `.env`, `.venv/`, `project.db`, `__pycache__/`, `.DS_Store` 제외 |

JWT 비밀키는 아래 명령으로 랜덤 생성해서 `.env`에 넣었다.
```bash
openssl rand -base64 32
```

## 3. 테이블 생성
`python -m asyncio`로 비동기 REPL을 열어 `init_db()`를 실행했다.
```python
>>> from database.orm import init_db
>>> from user.model import User, UserHealthProfile   # 모델을 import 해야 테이블이 만들어진다
>>> await init_db()
```
- 실행하면 `project.db` 파일이 생긴다. DBeaver에서 테이블을 확인했다.
- 처음에 `await init_db`로 괄호를 빠뜨려서 `TypeError: object function can't be used in 'await' expression` 에러가 났다. 함수는 호출해야 코루틴이 나오고, 그 코루틴을 await 해야 한다.
- `create_all`은 이미 있는 테이블은 건너뛴다. 컬럼을 고쳐도 기존 테이블에는 반영되지 않으므로 테이블을 지우고 다시 만들어야 한다.

### 테이블 구조
**user**
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | Integer | PK, 자동 증가 |
| email | String(256) | 중복 불가 |
| password_hash | String(256) | 해싱된 비밀번호 |
| created_at | DateTime | DB가 자동으로 채움 |

**user_health_profile**
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | Integer | PK, 자동 증가 |
| user_id | Integer | `user.id` 참조, 회원당 1개 |
| age | Integer | 나이 |
| height_cm | Float | 키 |
| weight_kg | Float | 몸무게 |
| smoking | Boolean | 흡연 여부 |
| exercise_per_week | Integer | 주당 운동 횟수 |
| created_at | DateTime | DB가 자동으로 채움 |

## 4. 회원가입 — `POST /users`
사용자 정보를 DB에 저장하는 기능이다.

### 1단계: 요청·응답 형태 정하기
- `user/request.py` → `SignUpRequest(email, password)`
- `user/response.py` → `SignUpResponse(id, email, created_at)`
- 응답에 `password_hash`가 나가지 않도록 `response_model`로 필드를 제한했다.

### 2단계: 비밀번호 해싱
비밀번호를 알아볼 수 없게 저장하되, 로그인할 때 다시 확인할 수 있어야 한다.
1. 해시는 되돌릴 수 없어야 한다 (복호화 불가).
2. bcrypt는 salt(랜덤 값)를 섞기 때문에 같은 비밀번호도 매번 다른 해시가 나온다. 확인할 때는 해시 안에 저장된 salt로 다시 해싱해서 비교한다 (`bcrypt.checkpw`).
3. bcrypt는 문자열이 아니라 bytes를 받으므로 `.encode()`로 바꿔서 넣는다.

```python
>>> import bcrypt
>>> plain_password = "mypassword"
>>> plain_password.encode()
b'mypassword'
>>> bcrypt.hashpw(plain_password.encode(), bcrypt.gensalt())
b'$2b$12$NwI2Bvf6ZVk9YoqXpuwHJ.8WxIYS/kHGH49KFteIyrTxa.9t7KP7a'
```

### 3단계: 라우터 핸들러
1. 이메일 중복 검사 → 있으면 `409 Conflict`
2. 비밀번호 해싱
3. DB 저장 → `commit` → `refresh` → `201 Created`로 응답

### 놓쳤다가 고친 부분
| 위치 | 문제 | 해결 |
|---|---|---|
| `router.py` | `response_model=...` 자리만 잡혀 있었음 | `response_model=SignUpResponse` |
| `router.py` | commit 뒤 `created_at`을 못 읽어 `MissingGreenlet` 에러 | `await session.refresh(new_user)` 추가 |
| `response.py` | ORM 객체를 응답으로 못 바꿈 | `ConfigDict(from_attributes=True)` 추가 |
| `config.py` | `open_api_key`가 `.env`의 `OPENAI_API_KEY`와 안 맞음 | `openai_api_key`로 수정 |

## 5. 로그인 — `POST /users/login`
시스템/서비스에 사용 인증을 받는 기능이다.

1. 이메일로 사용자 조회 → 없으면 `401`
2. `verify_password`로 비밀번호 확인 → 틀리면 `401`
   - 이메일이 틀렸는지 비밀번호가 틀렸는지는 구분해서 알려주지 않는다 (보안).
3. `create_access_token`으로 JWT 발급 → `{"access_token": "..."}` 응답

### JWT (JSON Web Token)
- 로그인에 성공하면 발급하는 출입증이다. 이후 요청 헤더에 `Authorization: Bearer <토큰>`으로 넣는다.
- payload에 `sub`(사용자 id)와 `exp`(만료 시간, 24시간)를 넣고 `JWT_SECRET_KEY`로 서명한다.
- `http://127.0.0.1:8000/docs`에서 회원가입 → 로그인으로 토큰을 받은 뒤 https://www.jwt.io/ 에 넣어 구조(header / payload / signature)를 확인했다.
