건강 프로필 저장, 그리고 OpenAI로 당뇨·고혈압 위험도 예측

어제 토큰으로 "누구인지"까지 알게 만들었다. 오늘은 그 사람의 건강 프로필을 저장하고, 프로필을 OpenAI에 보내 당뇨·고혈압 위험도를 받아 DB에 쌓는 API를 만들었다. 같은 요청을 하루에 여러 번 보내 요금이 새지 않게 24시간 제한도 걸었다.

00진행 현황

  1. 1개발 환경 세팅 (venv, 라이브러리, .env)완료
  2. 2DB 연결, user 테이블 생성완료
  3. 3회원가입 POST /users완료
  4. 4로그인 + JWT 발급 POST /users/login완료
  5. 5user_health_profile 테이블 생성완료
  6. 6건강 프로필 생성 POST /health-profiles오늘 완료
  7. 7health_risk_prediction 테이블 생성오늘 완료
  8. 8위험도 예측 + OpenAI 연결 POST /predictions오늘 완료

01전체 흐름

[건강 프로필] 토큰 → user_id
              → 이미 있으면 409 → 본문 + user_id로 저장 → refresh → 201

02건강 프로필 저장 POST /health-profiles

어제는 토큰에서 꺼낸 user_id만 돌려주는 상태였다. 오늘 중복 검사와 저장, 응답 양식까지 채웠다.

# [1] 프로필 중복 확인 → 회원당 1개
stmt = select(UserHealthProfile).where(UserHealthProfile.user_id == user_id)
result = await session.execute(stmt)
if result.scalar():
    raise HTTPException(status_code=409, detail="이미 건강 프로필이 존재합니다.")

# [2] 저장
profile_data = body.model_dump()                                  # Pydantic → dict
new_profile = UserHealthProfile(user_id=user_id, **profile_data)   # dict를 키워드 인자로 풀기
session.add(new_profile)
await session.commit()
await session.refresh(new_profile)
return new_profile
  • **profile_data는 age=30, height_cm=170.0, ...을 하나씩 적은 것과 같다. 요청 필드 이름과 모델 컬럼 이름이 같아서 가능하다
  • 응답 양식 UserHealthProfileResponse에도 ConfigDict(from_attributes=True)가 있어야 ORM 객체를 응답으로 바꾼다
  • APIRouter(tags=["User"]), tags=["Prediction"]을 붙여서 Swagger 화면이 기능별로 묶이게 했다

03예측 결과 테이블

class HealthRiskPrediction(Base):
    __tablename__ = "health_risk_prediction"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    user_id: Mapped[int] = mapped_column(ForeignKey("user.id"))     # unique 없음 → 1:N

    diabetes_probability: Mapped[float] = mapped_column(Float)
    hypertension_probability: Mapped[float] = mapped_column(Float)
    model_version: Mapped[str] = mapped_column(String(50))          # 어떤 모델로 예측했는지
    created_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
user_health_profilehealth_risk_prediction
회원당 개수1개 (unique=True)여러 개 (기록이 쌓임)
의미현재 상태예측할 때마다 남는 이력
model_version을 남기는 이유

모델마다 같은 입력에도 다른 확률이 나온다. 나중에 결과를 비교하거나 이상한 값이 나왔을 때 어떤 모델이 낸 값인지 알아야 하니까 예측 기록 쪽에 저장한다. 처음엔 이 컬럼을 프로필 모델에 잘못 넣어서 no such column 에러가 났다(아래 에러 기록).

04OpenAI 호출 prediction/llm.py

client = AsyncOpenAI(api_key=settings.openai_api_key)   # 키는 .env에서만

class RiskPredictionResult(BaseModel):
    diabetes_probability: float = Field(..., description="당뇨 위험도")
    hypertension_probability: float = Field(..., description="고혈압 위험도")

async def predict_health_risk(profile: UserHealthProfile, model_version: str):
    prompt = f"""
    다음 건강 정보를 기반으로 당뇨와 고혈압 위험도를 0과 1 사이로 계산하라.
    age: {profile.age}
    height_cm: {profile.height_cm}
    ...
    """
    response = await client.responses.parse(
        model=model_version,
        input=prompt,
        text_format=RiskPredictionResult,   # 이 양식대로만 답하게 강제
    )
    return response.output_parsed           # 이미 RiskPredictionResult 객체
  • 구조화된 출력: 답을 "당뇨 위험은 약 6%입니다" 같은 문장이 아니라 정해진 필드로 받는다. 문자열을 잘라서 숫자를 꺼낼 필요가 없다
  • description은 모델에게 각 필드가 무슨 뜻인지 알려 주는 힌트로도 쓰인다
  • API 키는 코드에 적지 않고 config.py가 .env에서 읽은 값을 쓴다

05동기 vs 비동기

함수 / 코드선택이유
predict_health_riskasync defOpenAI 응답을 몇 초 기다림. 기다리는 동안 서버가 다른 요청을 처리할 수 있어야 한다
BMI 계산 같은 순수 계산def기다릴 게 없다. async를 붙여도 빨라지지 않는다
HealthRiskPrediction(...)await 없음파이썬 객체를 만들 뿐, DB와 통신하지 않는다
commit / refresh / executeawaitDB와 실제로 주고받는 작업

기준은 하나다. 안에서 await 할 일이 있으면 async def, 없으면 def.

    new_prediction = HealthRiskPrediction(
        user_id=user_id,

        model_version=model_version,

왜 24시간 제한을 걸었나

프로필이 그대로면 몇 번을 물어봐도 같은 질문이다. 그런데 OpenAI는 호출할 때마다 요금이 나간다. 그래서 같은 사용자가 하루 안에 다시 요청하면 LLM을 부르기 전에 409로 막는다. 비싼 작업 앞에 싼 검사(DB 조회)를 먼저 두는 순서가 중요하다.

07Body(embed=True)와 Literal

코드보내야 하는 본문
Body("gpt-5-mini")"gpt-5-mini" (문자열 하나)
Body("gpt-5-mini", embed=True){"model_version": "gpt-5-mini"}
  • 본문 값이 하나뿐이면 FastAPI는 그 값을 그대로 받는다. embed=True를 주면 파라미터 이름을 키로 한 JSON으로 감싼다. 나중에 필드가 늘어나도 형태가 같아서 편하다
  • Literal["gpt-5-mini", "gpt-6-luna"]: 이 두 값만 허용. Swagger에서 드롭다운으로 보이고, 다른 값이면 422
  • 기본값이 있어서 본문을 비워도 동작하지만, 테스트할 때는 {"model_version": "gpt-5-mini"}를 넣어 어떤 모델을 쓰는지 분명히 했다

08Swagger 테스트

  1. POST /users/login → access_token 복사
  2. 오른쪽 위 Authorize에 토큰 붙여 넣기
  3. 프로필이 없으면 POST /health-profiles로 먼저 만들기
  4. POST /predictions에 {"model_version": "gpt-5-mini"} → 201
  5. 한 번 더 실행 → 409 24시간 내에 예측한 결과가 존재합니다.

테스트 프로필: 30세, 170cm, 75kg, 비흡연, 주 3회 운동

프로필이 있는데 404가 났다

테스트 데이터를 지우고 계정을 새로 만들었는데, Authorize에는 지우기 전 계정의 토큰이 남아 있었다. JWT는 서명과 만료만 검사하니까 DB에서 지워진 계정의 토큰도 24시간 동안은 통과하고, 그 id로 프로필을 찾으니 404가 났다. 다시 로그인해서 새 토큰으로 Authorize하니 해결됐다. verify_user에서 사용자가 DB에 실제로 있는지까지 확인하면 이런 경우에 401이 나와서 원인이 더 잘 보인다.

★오늘의 핵심 5줄

  1. user_id는 본문이 아니라 토큰에서 꺼내고, body.model_dump() + **로 나머지 필드를 한 번에 넣는다
  2. 프로필은 회원당 1개(현재 상태), 예측은 여러 개(이력)이다. 어떤 모델이 낸 값인지 model_version으로 남긴다
  3. responses.parse(text_format=...)로 LLM 답을 정해진 필드로 받는다
  4. await 할 일이 있으면 async def, 객체 생성에는 await를 붙이지 않는다
  5. 비싼 LLM 호출 앞에 24시간 중복 검사(409)라는 싼 검사를 먼저 둔다
